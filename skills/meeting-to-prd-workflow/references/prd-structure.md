# PRD 结构参考

## 功能页面模板

每个功能页建议按以下顺序：

1. `3.x.x 页面名称`
2. `页面类型：宜搭表单页 / 流程页 / 自定义页面 / 报表页 / 地图页 / 移动端页面 / AI页面 / 集成记录 / 打印模板`
3. `字段标记：* 为必填；加粗字段表示由关联页面、主数据、地图点位、任务或知识库带出。`
4. 页面布局或表单原型
5. 明细表/子表/地图图层/看板指标/AI输出区，按页面类型选择
6. `审批/流转：...`，如适用
7. `功能描述：`
8. `业务规则：`
9. `待确认事项：`，如适用
10. `客户原始表单截图：`
11. 插入一张或多张截图；没有原始表单时写明“待客户补充”

## 业务域生成规则

业务域必须从项目材料中抽取，不使用固定行业域。常见宜搭项目可以按能力拆分：

- 目标与策略：战略目标、价值指标、管理口径、项目里程碑。
- 主数据：门店、渠道、客户、产品线、区域、人员、组织、供应商等，以材料为准。
- 业务执行：巡检、拜访、审批、任务派发、问题整改、活动执行、售后处理等。
- 数据呈现：地图可视化、台账、经营看板、排行榜、趋势分析、预警列表。
- AI 能力：知识库检索、智能问答、图片识别、评分、摘要、预测、异常识别。
- 集成与移动端：钉钉、高德地图、外部系统、消息通知、移动端填报。

如果项目材料明确是供应链、制造或财务项目，可以生成对应业务域；否则不得默认写入这些域。

## 字段逻辑用语

保持以下写法稳定，并按项目替换来源对象：

- `规则生成`：系统按编号规则生成。
- `默认当前人员` / `默认当前部门` / `默认当前日期`。
- `主数据带出`：从门店、渠道、客户、产品、人员、组织等主数据带出。
- `关联页面带出`：从上游表单、任务、审批或报表筛选条件带出。
- `地图点位带出`：从地图、门店经纬度或行政区划带出。
- `知识库检索`：从文档、制度、策略材料、外部知识源检索。
- `AI识别/AI评分/AI摘要/AI预测`：由模型生成，必须保留人工确认或解释入口。
- `自动计算`：金额、数量、得分、状态、风险等级、完成率、覆盖率、趋势等。
- `手动填写/可调整`：业务用户可覆盖或补充。

示例用语只能作为表达方式参考，不能把示例对象当作项目范围。

## 典型闭环路径

先按材料判断项目类型，再选择或组合闭环路径：

- 市场/门店/巡检类：策略目标 -> 门店/渠道样本 -> 地图可视化 -> 巡检任务派发 -> 移动端反馈 -> 图片/位置/表单采集 -> AI识别/评分 -> 异常预警 -> 区域复盘 -> 经营看板。
- AI 知识库类：资料归档 -> 知识切片/标签 -> 权限控制 -> 智能检索/问答 -> 答案引用来源 -> 人工反馈 -> 知识更新。
- 流程审批类：申请 -> 审批 -> 执行 -> 归档 -> 通知 -> 台账/报表。
- 经营看板类：数据源 -> 指标口径 -> 数据处理 -> 可视化组件 -> 下钻明细 -> 预警 -> 决策动作。
- 供应链/生产/财务类：仅在材料明确出现时，按真实单据链路生成。

## 缺失材料处理

不要只写“待客户补充”。应先创建逻辑页面，至少包含：

- 来源状态说明
- 页面目标和用户
- 核心字段、指标或图层
- 明细表、任务列表、看板组件或 AI 输出区
- 业务规则
- 待确认事项
- 截图占位标签

同时把缺失原始表单写入客户待补资料清单。
