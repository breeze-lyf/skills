# 表单整理与结构化参考

## 客户材料盘点字段

每个源文件至少记录：

- 原始路径
- 规范路径
- workbook/sheet 或页名
- 客户当前表单名称
- 对应 PRD 页面
- 页面类型
- 来源状态：客户已提供 / 系统推导 / 客户暂未提供 / 背景材料
- 处理方式：直接页面、拆分页面、仅报表、地图图层、AI知识源、附录、重复、排除、待确认

## 推荐目录

目录按项目材料动态生成。通用建议：

- `0.范围合同`
- `1.会议纪要与需求`
- `2.客户原始表单`
- `3.主数据资料`
- `4.流程与任务`
- `5.报表看板与地图`
- `6.AI知识库与算法资料`
- `7.集成与权限`
- `9.待确认资料`

如果材料明确属于某行业或某业务域，可把 `3-7` 替换为项目真实域，例如门店巡检、渠道运营、售后服务、经营看板、供应链协同等。不得默认使用上一项目的业务域。

## 文件命名规则

推荐格式：

`NN_业务对象_补充标识_日期或版本.ext`

示例：

- `01_会议纪要_启动会_20260601.md`
- `02_门店样本清单_杭州200家_20260601.xlsx`
- `03_巡检任务表_移动端字段_20260601.xlsx`
- `04_AI知识库资料清单_20260601.xlsx`
- `05_地图图层与状态规则_20260601.xlsx`

截图命名：

`规范文件名__sheet名.png`

## 需要拆分的情况

一个客户 workbook 或一段会议需求中存在不同业务用途时，要拆成多个 PRD 页面：

- 地图可视化 vs 门店档案 vs 巡检任务
- 巡检记录 vs 整改闭环 vs 区域复盘
- 知识库资料管理 vs 智能问答 vs 答案反馈
- 指标口径表 vs 经营看板 vs 预警列表
- 表单采集 vs 审批流转 vs 台账报表

拆分标准是“用户目的不同、数据结构不同、流转责任不同、宜搭页面形态不同”。示例仅说明拆分方法，不代表必须建设这些页面。

## 需要结构化的情况

客户原表或会议纪要中的大段文字，如果能拆成明确字段、指标、任务规则或明细表，就不要只保留多行文本：

- 巡检要求 -> 门店、巡检人、巡检日期、位置、照片、评分项、异常类型、整改要求。
- 地图状态 -> 点位、经纬度、状态颜色、预警原因、负责人、更新时间。
- AI知识库 -> 资料名称、来源、标签、权限、更新时间、适用场景、引用规则。
- 经营目标 -> 指标名称、口径、基线值、目标值、周期、负责人、数据来源。
- 任务派发规则 -> 触发条件、派发对象、截止时间、通知方式、超时升级。

只有无法合理结构化的内容，才放入整行“其他说明”。

## 截图位置

截图必须放在系统设计字段和业务规则之后，不要放在页面开头。

如果某页没有客户原始表单，仍保留 `客户原始表单截图：` 标签，并写“待客户补充”或留空。
