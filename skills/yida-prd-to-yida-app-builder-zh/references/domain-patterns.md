# 常见模块模式

这些模式不是硬规则，而是审查 PRD 和设计宜搭表单时的起点。

## 产品生命周期

常见对象：

- 候选产品主数据
- 正式产品主数据
- 样品/测试/审厂/终测单据
- 上架、入库、品控、下架单据

关键原则：

- 候选阶段关联候选产品。
- 正式运营阶段关联正式产品。
- 正式产品通常由品鉴/终测通过生成，不让普通用户手动新建。
- 上下架通过状态回写控制下游可选范围。

## 开店 / 营建流程

常见对象：

- 门店主数据
- 开店立项
- 证照登记
- 物业信息
- 实地勘测
- 门店设计
- 施工进场/进度/验收

关键原则：

- 门店主数据应由立项完成生成或更新。
- 后续证照、物业、设计、施工都应关联门店。
- 每个阶段的结果要回写门店或项目状态。
- 财务、供应链、人资、增长等账号或建档通知要有明确责任人和完成状态。

## 报修流程

常见对象：

- 设备主数据
- 问题类型/问题归属
- 维修师傅
- 报修申请
- 维修确认
- 门店问题确认
- 维修物料明细

关键原则：

- 门店和设备应关联选择。
- 问题类型应自动带出处理责任或维修师傅。
- 报修单状态应由维修确认和门店确认回写。
- 物料消耗应能关联到配件库存或配件档案。

## 巡店流程

常见对象：

- 巡店模板分组
- 巡店模板
- 巡店任务
- 巡店报告
- 整改记录

关键原则：

- 模板是主数据，任务和报告是业务单据。
- 巡店任务选择模板后，应生成或带出检查项。
- 报告结果应回写任务状态。
- 不合格项应进入整改闭环，而不是停在报告里。

## 增长 / 活动 / 设计申请

常见对象：

- 活动申请
- 品牌设计申请
- 产品下单
- 门店/活动/物料主数据

关键原则：

- 申请类表单通常需要审批、附件、期望完成时间和验收结果。
- 涉及门店或产品时应关联主数据。
- 设计完成、物料下单、活动复盘应形成闭环状态。

## 财务 / 合同 / 报销同步

常见对象：

- 合同档案
- 采购合同
- 付款单
- 报销单
- 立项/项目

关键原则：

- 外部系统可能是主数据源，先确认同步方向。
- 有合同则按合同关联项目，无合同则需要明确匹配条件。
- 不要把外部系统权威字段改成宜搭手填，除非业务确认。
