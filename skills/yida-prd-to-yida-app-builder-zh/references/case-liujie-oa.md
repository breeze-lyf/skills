# 案例：六姐OA 项目历史参考

这份参考用于处理六姐OA 项目，或在其他项目中需要查看一个完整宜搭模块从蓝图到闭环落地的样板时使用。

产品中心只是已验证样板，后续应把同一方法复用到营建、报修、巡店、增长、供应链、财务等模块。

## 完整蓝图范围

蓝图文档不是单一产品模块，而是一个 OA 协同办公平台方案，包含：

- 项目背景和系统架构
- 消息中心
- 主数据同步
- 业务单据同步
- 系统集成
- 单点登录
- 营建中心：开店流程、报修流程、账号管理
- IT中心：账号创建与系统账号协同
- 产品中心：产品生命周期
- 供应链中心
- 增长中心：活动申请、品牌设计申请、产品下单
- 运营中心：巡店模板、巡店任务、巡店报告
- 优化中心
- 总经办中心
- 财务中心
- 一店一群
- 海康、每刻、乐才等集成

所以 Skill 的目标应是“PRD/蓝图 -> 宜搭应用闭环搭建”，而不是只服务产品模块。

## 原始目标

用户正在钉钉宜搭上建设成都六姐OA 协同办公平台。产品中心是当前已实践最深的模块，其核心目标是管理冒菜产品的全生命周期：

信息收集 -> 寻样 -> 测试/品鉴 -> 审厂 -> 终测 -> 上架 -> 入库/品控 -> 下架。

最重要的原则是数据一致性：凡是选择已有产品的地方，都应关联正确的产品来源，不能让用户自由手打。

## 蓝图理解

早期蓝图列出了 18 个产品中心表单：

- 展会报告
- 产品登记
- 产品档案
- 样品需求
- 品鉴会测试
- 样品试样交接
- 审厂信息表
- 终测需求
- 终测信息
- 终测报告
- 六姐产品库
- 首批大货排产周期表
- 产品入库
- 品控抽检
- 日常仓库检查
- 飞行检查
- 产品上架
- 产品下架

后续业务澄清：`展会报告` 在当前实施里不作为独立页面存在，展会产品统一通过 `产品登记` 录入，来源选择“展会”。

## 实施阶段

### 阶段 1：AI/openyida 生成表单

- 核心表单用 `openyida create-form create` 批量创建。
- 初始 JSON 表单结构可用但很朴素，缺少同事手工搭建页面那种 UI 质感。
- 一些页面最初没有完整的关联字段，因为 CLI 更擅长快速生成结构，不一定一次性表达所有高级宜搭行为。

### 阶段 2：补 Schema 和关联字段

- `六姐产品库` 补充了厂家、保质期、单价、上架状态、源产品编号等关键字段。
- 产品选择字段陆续改成或补成 `AssociationFormField`。
- 候选产品阶段关联 `产品档案`。
- 正式产品阶段关联 `六姐产品库`。
- 增加数据回填规则，让规格、包装规格、口味、厂家、编号等自动带出。

### 阶段 3：修 UI

- 用户发现同事搭的页面有 UI，而 openyida 生成的页面很普通。
- 对多个表单套用红色分区和两列布局。
- 电脑端两列，手机端自动一列。
- 避免把成员、附件、多行文本、子表等组件塞进窄列。

### 阶段 4：修业务逻辑

- 用户明确指出：`六姐产品库` 的产品应从品鉴通过或终测通过流转过来，不是重新手动创建。
- `品鉴会测试` 是一场多产品，通过子表记录多个产品。
- `产品档案` 和 `六姐产品库` 权限被收紧，普通成员不应随意维护系统生成的主数据。
- 下游表单按 `六姐产品库.上架状态` 过滤产品。

### 阶段 5：自动化闭环

当前有效或需保留的产品中心自动化包括：

- `【产品登记】自动生成产品档案`
- `【品鉴会测试】新增六姐库`，同事创建，注意保留负责人边界
- `【样品试样交接】测试通过后进入产品档案`，同事创建，注意保留负责人边界
- `【终测信息】通过后同步六姐产品库`
- `【产品上架】回写六姐产品库状态`
- `【产品下架】回写六姐产品库状态`

当前产品中心主链路：

产品登记 -> 产品档案 -> 品鉴会/试样/审厂/终测 -> 六姐产品库 -> 产品上架 -> 入库/品控/下架 -> 六姐产品库状态回写。

## 已沉淀经验

- openyida 很适合快速生成基础表单，但不能覆盖所有 UI、高级关联、复杂自动化、审批通知和定时任务。
- PRD 可能不完美，必须先审主数据来源和业务闭环。
- 正式结果库不能随意手工创建，应由业务通过后流转生成。
- 关联字段对象写入文本字段会出问题，需要文本辅助字段。
- UPSERT 更新时不能用空辅助字段覆盖成熟主数据。
- 自动化命名要符合项目习惯，例如 `【表单名】动作`。
- 每次修改都要更新交接文档，否则换 Agent 后很难接续。

## 仍需警惕

- `审厂汇总` 是否还像人工汇总，是否应由一审/二审自动生成或更新。
- `产品入库` 是否必须经过上架或首批大货排产后才能入库。
- 通知、审批、定时任务仍需按部门协作进一步补齐。
